# 大规模场景深度融合：降低内存与自适应减点

本文梳理 `DensifyPointCloud` 针对大规模数据所做的两项改动：

1. **流式融合**（`--stream-fusion`）：边融合边写出 PLY，不在内存中保留整个稠密点云。解决的内存不足。
2. **特征自适应简化**（`--simplify-adaptive`）：在流式融合输出的同时，平坦区大幅减点，特征区保留细节，密度过渡平滑。

两项改动都是可选的，默认关闭；关闭时行为与原版 openMVS 完全一致。

---

## 1. 问题分析

### 1.1 现象

深度图估计阶段（`--fusion-mode 1`）一次只处理一张参考图及其邻居，内存可控。深度融合阶段（`--fusion-mode 0 --fusion-filter 2`，即 `DenseFuseDepthMaps`）在大场景上经常内存不足。

### 1.2 原因

原始 `DenseFuseDepthMaps` 的内存由三部分组成：

| 部分 | 内容 | 随什么增长 |
|---|---|---|
| 输出点云 `PointCloud` | `points`（12 B）、`colors`（3 B）、`normals`（12 B），以及每个点各一个动态数组 `pointViews`、`pointWeights`（每个数组有对象头开销，再加每个视图 4 B） | **融合出的总点数** |
| 深度图缓存 `DMapCache` | 深度图、法线图、置信度图、彩色图 | 按“可用物理内存”自动扩张 |
| 访问掩码 `arrUseMask` | 每张深度图一个位图，标记哪些像素已被融合 | 所有深度图的像素总数 |

其中第一项是主要矛盾。点数与深度图分辨率的平方成正比，`--resolution-level` 从 3 降到 2 或 1，点数会变为约 4 倍或 16 倍。而且这些点直到融合结束、写 PLY 之前都必须全部驻留内存。每个点的 `pointViews` 和 `pointWeights` 都是独立分配的小数组，堆碎片使实际占用进一步放大。实测数据（180 张深度图，`--resolution-level 2`，约 1908 万点）峰值约 **8.37 GB**。

第二项问题在于缓存按“可用内存”自动扩张，会与第一项相互挤占。

### 1.3 思路

- 点一旦融合完成就不会再被修改。因此可以**立即写盘**，不必保留在内存中；`pointViews`、`pointWeights` 也只需输出视图个数（PLY 里本来就只有 `views` 计数）。
- 深度图缓存改为**有明确字节预算的 LRU 缓存**，访问掩码换出到磁盘。
- 点数过多的根源是原始点间距（约 0.66 GSD）远小于实际可分辨的细节尺度。可以按局部 GSD 和局部几何特征**只在平坦区减点**，在不牺牲细节的前提下大幅减少点数。

## 2. 流式融合（降低内存）

涉及文件：`libs/MVS/PointCloud.h/.cpp`（`PointCloudStreamWriter`）、`libs/MVS/SceneDensify.cpp`（`StreamingFusionCache`、`DenseFuseDepthMaps`）、`libs/MVS/Scene.h`、`libs/MVS/SceneDensify.h`、`apps/DensifyPointCloud/DensifyPointCloud.cpp`。

### 2.1 总体流程

```
加载 scene.mvs
        │
        ▼
估计缺失的深度图（标准逐图估计；已有 .dmap 跳过，每张保存后立即释放）
        │
        ▼
重新准备视图（只加载相机与邻居关系，不加载深度图；估计失败、没有 .dmap 的视图跳过）
        │
        ▼
StreamingFusionCache::Initialize
  · 逐个校验已有 .dmap 文件头：尺寸、相机 K/R/C、文件长度
  · 为每张深度图在磁盘掩码文件 masks.bin 中分配位图空间
  · 预估每张深度图驻留所需字节
        │
        ▼
循环：选下一张参考深度图（FetchBestNextDMapIndex）
  · Pin(参考图) + Pin(各邻居图)：按需从磁盘加载，并从 masks.bin 读入掩码
  · 原有 dense-fuse 逻辑：投影、深度/法线一致性检验、累加位置/颜色/法线
  · 每融合出一个点 → 立即 PointCloudStreamWriter::Write（或交给简化器）
  · FinishRound：把本轮用过的掩码写回 masks.bin 并释放
        │
        ▼
PointCloudStreamWriter::Finish
  · 回填 PLY 头中的点数，原子替换目标文件
```

### 2.2 `PointCloudStreamWriter`：增量写 PLY

- 构造时在输出目录创建临时目录 `<输出>.ply.stream-<唯一名>`，向其中的临时 PLY 写入文件头。点数字段先写成**十位数字的占位符**，因为最终点数事先未知。
- `Write()` 每次追加一条二进制记录：`x y z (float) [r g b (uchar)] [nx ny nz (float)] views (uchar)`，格式与原 `PointCloud::Save` 输出的二进制 PLY 完全相同。
- `Finish()` 原地改写点数字段并 flush，然后用 `MoveFileEx(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`（Windows）或 `rename`（其他平台）**原子替换**目标文件。任何环节失败都不会覆盖已有的输出文件。
- 点数上限沿用原 PLY 写出器的 2,147,483,647，超过时报错。
- `GetScratchPath()` 提供临时目录，融合掩码文件和简化的临时文件也都放在这里，结束后统一删除。

内存效果：输出点云的占用从 O(点数) 降为 O(1)，只剩一个文件写缓冲。

### 2.3 `StreamingFusionCache`：有预算的深度图缓存

由 `--stream-fusion-cache-mb`（MiB）控制。预算覆盖以下内容：常驻的深度图、法线图、置信度图、彩色图（仅 `--estimate-colors 2` 时）、当前轮次的访问掩码，以及一次 RGB 图像解码的临时缓冲。

- **Initialize**：读取每个 `.dmap` 的文件头。尺寸与当前分辨率不一致、相机参数相对误差超过 1e-8、文件被截断时，直接报错，不会悄悄重算。随后计算每张图的驻留字节估计 `residentEstimate` 与解码开销 `decodeBytes`，并为它在 `masks.bin` 中分配 `ceil(像素数/位宽)` 个字的偏移量。
- **Pin(id)**：本轮要用到的图（参考图及最多 `nMaxViewsFuse` 个邻居）被“钉住”。
  - 若未缓存，先调用 `MakeRoom` 按 LRU 淘汰未钉住的图，然后从磁盘加载。若加载后的实际大小超过估计，按错误处理，以免预算被悄悄突破。
  - 掩码第一次使用时清零，之后都从 `masks.bin` 读回。
  - 钉住的图即使全部加入也放不下时，会明确报错，提示加大 `--stream-fusion-cache-mb`；**不会悄悄丢弃邻居**，因为那会改变融合结果。
- **FinishRound**：本轮结束后，把所有钉住图的掩码写回 `masks.bin` 并释放，深度数据保留在 LRU 中供后续复用。
- **调度与缓存解耦**：`FetchBestNextDMapIndex` 的选择依据是“曾经被加载过”（`usedForScheduling`），而不是“当前仍在缓存中”。因此**缓存大小只影响磁盘 I/O，不影响融合顺序和结果**。

磁盘开销：掩码文件每个深度图像素 1 bit；PLY 每点 16～28 字节，取决于是否输出颜色和法线。

### 2.4 适用范围与限制

- 深度图缺失时会先自动估计（与 `--fusion-mode 1` 相同的逐图流程），已有的深度图直接复用；也可以先单独用 `--fusion-mode 1` 生成，再用 `--fusion-mode 0 --stream-fusion 1` 融合，两次的工作目录、分辨率参数必须一致。
- 仅支持 `--fusion-filter 2`、`--geometric-iters 0`、`--postprocess-dmaps 0`；颜色、法线估计只能取 0 或 2。
- 不支持依赖内存点云的后处理：融合后的颜色/法线估计、分割、点云滤波、`--normalize-coordinates`。输出只有 PLY，不生成新的 `.mvs`，也不包含逐点的视图 ID 和权重，只有视图个数。
- 保留 ROI 裁剪功能（裁剪后点的写出顺序可能不同，但点集相同）。

### 2.5 结果

| | 点数 | 峰值内存 | 耗时 |
|---|---:|---:|---:|
| 原始融合 | 19,082,657 | ~8.37 GB | 2m14s |
| 流式融合（cache 768 MiB） | 19,082,657 | **~880 MB** | 3m27s |

两者输出的点集完全一致。`--stream-fusion-cache-mb` 的选取：至少要装得下“一张参考图 + 所有邻居”的深度数据和掩码，再留一定余量减少反复加载。本数据建议 768。缓存再大对速度的提升有限。

## 3. 减点的探索过程

### 3.1 第一版：保守平面简化（已废弃）

做法：把点划入 8～16 倍 GSD 的格子，对每个格子做稳健平面拟合（MAD）。满足条件的格子（内点占 80% 以上、噪声 ≤ 0.75 GSD、法线和颜色一致）在平面上按 1.5 GSD 的网格各取一个代表点；格子边缘的点则全部保留。

结果：真实数据只减少 **14.7%**，而且放大后能看到**一个个方框**。原因如下：

1. **二值决策**：每个格子要么全部简化，要么全部保留，相邻格子的密度出现突变。
2. **格子边界保留带**：为了不产生缝，格子边缘的点被全部保留，形成一圈高密度的框线。
3. **规则网格采样**：代表点排列成规则网格，与相邻格子的原始不规则分布形成明显的纹理差异。
4. **判定过严**：实际噪声约 0.79 GSD，法线偏差约 10°，大量格子不满足平面条件，因此减点比例很低。

结论：任何“按格子/按块一刀切”的方案都会在边界上留下痕迹。必须改为**逐点、连续、无网格**的方案。

### 3.2 第二版：特征自适应泊松盘采样

设计原则：

- **逐点**计算一个连续的特征分数，而不是按格子做二值判定；
- 目标间距随特征分数**连续变化**，并做空间平滑，使密度只会渐变；
- 用**可变半径泊松盘采样**选点，结果天然是不规则的蓝噪声分布，没有网格纹理；
- **只保留原始点**，不移动、不平均，输出是原始结果的严格子集；
- 分块只是实现手段：块与块之间带重叠区，并传递边界处的采样决策，从而保证结果与“全局一次处理”等价，没有接缝。

先用 Python 原型（numba + scipy）在真实数据中切出的三块 50×50 m 区域上验证：平坦区块减点约 66%，被删点到最近保留点的距离 p99 约为 1.6 GSD，可视化无方框。之后才移植为 C++。

### 3.3 第三版：消除平面上的密度“边痕”（当前方案）

第二版在真实数据上仍能看到：同一块平面（田地）上，深色区稀、浅色区密，分界很锐利。用原型在 6 个 40×40 m 区块上逐项排查，原因有 5 个：

1. **稀疏度项多余**：原始点偏稀的区域被整片判为特征。泊松采样本来就不会删除没有邻点的点，这一项只会制造“稀疏区变密”的边界，已删除。
2. **2g 邻域的曲面变化度主要反映噪声**：平面噪声 σ ≈ 0.4–0.45 GSD 时，2g 邻域的曲面变化度约 0.05–0.24，正好落在原阈值区间 0.12–0.25 内，不同材质的噪声差异直接变成密度差异。改为 **3g 邻域**（噪声的影响约减半），并用宽区间的**线性映射** 0.03→0.25 代替 smoothstep。
3. **smoothstep 使分数接近二值**，加上点密度 ∝ 1/r²，密度变化集中在过渡带的一端。改为线性映射，并在**对数域**限制间距的空间梯度（见 4.3）。
4. **各向同性的覆盖判定把厚噪声层当成多层**：在密区，水平 0.5g 范围内的保留点沿法线方向分布约 1.9g。噪声层比 `r` 厚时，沿法线叠在一起的点彼此不在对方的球内，于是都被保留，看起来像多层。改为**沿切平面量距离**，法线方向只需落在噪声带内（见 4.4）。
5. **纹理权重过高**：亮度变化（材质、阴影）不应与几何边缘同等加密。纹理项权重降为 0.5，即纹理处间距约 1.5 GSD。

各项在原型上的效果（0.4 m 网格对数密度梯度 p95，越小边痕越弱）：线性映射 + 对数域梯度限制比第二版低 10%–20%；再加各向异性覆盖，又降低 10%–25%，保留率也从约 19% 降到约 15%。

## 4. 特征自适应简化：原理

涉及文件：`libs/MVS/PointCloudSimplify.h/.cpp`（新增）。`SceneDensify.cpp` 在融合输出处计算每点 GSD 并调用简化器。

### 4.1 局部 GSD：所有长度的统一尺度

对每个融合点 `X`（法线 `n`），在每个支持视图中计算“表面上一个像素对应的世界长度”（`SurfacePixelSize`）：

1. 取切平面上两个正交方向 `u`、`v`；
2. 求它们经透视投影后的像素速度（投影雅可比 `J`，2×2）：
   `J = K_xy · (R·t − (p/p_z)·(R·t)_z) / p_z`，其中 `t ∈ {u, v}`，`p = R(X − C)`；
3. `JᵀJ` 的最大特征值 `λ_max` 对应切平面上分辨率最高的方向，`gsd = 1/√λ_max`；
4. 掠射角过大（`λ_min < 0.01·λ_max`）或点在相机背后时，该视图无效。

取所有有效视图中 **20% 分位数**作为该点的 GSD `g`：偏向分辨率最好的视图，同时排除个别异常视图。场景中位数为 `g0`，每点 GSD 截断到 `gcap = 2·g0`，以免远处或掠射的点把半径放得过大。没有有效 GSD 或法线的点直接原样输出（日志中的 unknown-scale points）。

真实数据：`g` 的 p10/p50/p90 为 0.118/0.139/0.146，原始点间距约 0.66 GSD，说明原始点云远比可分辨的细节密。

### 4.2 特征分数 `s ∈ [0, 1]`

对每个点取半径 `3g` 内的邻点，计算协方差矩阵的特征值 `λ0 ≤ λ1 ≤ λ2` 以及亮度（0.299R+0.587G+0.114B）的标准差，把各项映射到 [0, 1] 后取最大值（`ramp(x, a, b) = clamp((x−a)/(b−a), 0, 1)`）：

| 指标 | 公式 | 映射 | 识别对象 |
|---|---|---|---|
| 曲面变化度 | `λ0 / (λ0+λ1+λ2)` | `ramp(·, 0.03, 0.25)` | 边缘、角点、屋脊、杂乱区域 |
| 线状度 | `(λ2−λ1) / λ2` | `smoothstep(·, 0.7, 0.9)` | 电线、杆、细条带 |
| 亮度标准差 | `std(luma)` | `0.5 · ramp(·, 10, 50)` | 纹理、标线、颜色边界（仅在有颜色时） |

- 用 3g 而不是 2g：邻点更多，噪声对曲面变化度的影响约减半，同一平面上不同材质的分数差距变小。
- 用宽区间的线性映射：分数随几何变化连续变化，不会在某个阈值附近“跳变”。
- 不再有稀疏度项（原因见 3.3）。邻点少于 3 个的孤立点 `s = 1`。

同时记录三项供采样使用：PCA 最小特征向量作为局部法线 `n_p`；邻域质心 `m_p`；沿法线的噪声标准差 `σ_p = √λ0`。

### 4.3 目标间距与平滑过渡

```
r_raw(p) = g · ( min + (max − min) · (1 − s) )      默认 min = 1.0, max = 2.0
```

- 特征点 (`s = 1`)：每 1 GSD 留一个点，即在可分辨极限上保留细节；
- 平坦点 (`s = 0`)：每 2 GSD 留一个点，点数约为原来的 (0.66/2)² ≈ 1/9，加上噪声和过渡区，实际减点约 60%～70%。

然后限制间距的空间梯度（`--simplify-transition T`，默认 30）：

```
ln r(p) ≤ ln r(q) + k · dist(p, q)，   k = ln2 / (T · g0)
```

即沿表面每走 `T` 个中位 GSD（默认约 4 m），间距最多翻一倍。

- 在对数域限制梯度：点密度 ∝ 1/r²，对数域等比例变化使**密度的相对变化均匀分布**在整个过渡带上，而不是集中在一端；
- 实现：把点放入边长 `g0` 的体素，每个体素取块内点的最小 `ln r`，在被占用体素的 26 邻接图上做多源 Dijkstra（边权 `k ·` 体素中心距离）。这是精确的距离变换，只沿实际存在的表面传播，不会跨越空洞；
- 每点 `r ← min(r, exp(G(体素) + k · 0.87 · g0))`，后一项是体素内的最大偏差；
- 只会让间距**变小**（加密），不会让特征点变稀；
- `T = 0` 关闭此步骤。

### 4.4 可变半径泊松盘采样

1. **访问顺序**：按 `s` 降序（先保证特征点）→ 视图数降序（观测越多越可靠）→ 点 ID 的哈希（打散顺序，避免沿扫描线产生规律）。
2. 对每个点 `p`，记 `d = q − p`、法向偏移 `h = n_p · d`、噪声带 `b = min(error·g + 2.5·σ_p, r_p)`，检查已保留点 `q` 中是否存在一个点同时满足：
   - **沿切平面的距离** `√(|d|² − h²) ≤ min(r_p, r_q)`：取两者中较小的半径，使特征点不会被附近平坦点的大半径“吃掉”；
   - 且满足下列之一：
     - `|d| ≤ min · g`：比最小间距还近，无论如何都算覆盖（任何地方都不会比 1 GSD 更密）；
     - `|h| ≤ b` 且 `|n_p · (m_q − m_p)| ≤ error · g`（默认 0.5 GSD）：`q` 在 `p` 所在噪声层内，且两点的**邻域质心**在同一表面上。
   若存在这样的点，`p` 被删除；否则保留 `p`。
3. 用切平面距离而不是球距离：厚噪声层中沿法线叠在一起的点会互相覆盖，不会被保留成“多层”（3.3 的原因 4）。
4. 用邻域质心而不是点本身判断是否同一表面：单点受噪声影响大，质心是 3g 邻域的平均，更稳定；而**双层表面**（如屋檐与地面、桥面上下表面）、**小起伏**（高于 0.5 GSD）的质心偏差明显，仍不会被另一层的点代替。

由此得到的保证：

- 每个被删点沿切平面在 `max·g` 范围内都有一个保留点，二者局部表面（质心）的落差不超过 `error·g`；
- 输出点是原始融合点的严格子集，颜色、法线、视图数原样保留；
- 采样结果是不规则的蓝噪声分布，没有规则网格，也就不会出现方框纹理。

### 4.5 外存分块处理

简化需要邻域查询，全部点同时载入又会回到内存问题。因此采用磁盘分块：

1. **写入阶段**（与融合同时进行）：每点写一条 48 字节的记录 `Record{point, normal, gsd, views, id, color, halo}` 到 `spool.bin`，同时统计 GSD 直方图（对数分箱）和 xy 包围盒。融合缓存在简化开始前释放，两者不会同时占用内存。
2. **确定参数**：
   - `g0` = GSD 中位数，`gcap = 2·g0`；
   - 重叠区宽度 `halo = (W + 3·gcap + √2·max·gcap) · 1.01`，其中 `W = log2(max/min) · T · g0 + 2·g0` 是间距过渡的影响距离（默认 32g0）；`3·gcap` 是特征邻域半径；`√2·max·gcap` 是泊松冲突的搜索半径（切平面距离 + 噪声带）。默认参数下约 44·g0；
   - 块边长 = `max( sqrt(面积 · (预算/224 B) / 点数), 4·halo )`，即按平均密度让每块约容纳“预算 / 224 字节”个点（每点工作内存约 224 B，含特征、质心、体素和堆）。块边长 ≥ 4·halo，保证重叠区只涉及 8 个直接相邻的块。
3. **分块**：顺序扫描 `spool.bin`，把每个点写入其所属块的文件；如果它与相邻块的距离不超过 halo，再以 halo 副本写入相邻块。每轮最多同时打开 256 个块文件，块数更多时分多轮扫描。
4. **逐块处理**（按列优先的固定顺序）：
   - 读入块的全部记录（核心点 + halo 点），建立 `2g0` 的均匀网格做半径查询（单元键为 3×21 位打包，按 z 连续存放以便范围扫描）；
   - 用 OpenMP 并行计算特征和半径，再做体素 Dijkstra 梯度限制。由于 halo 覆盖了全部依赖距离，核心点的计算结果与全局计算相同（GSD 在 halo 范围内变化时为近似）；
   - halo 点如果已在之前处理的相邻块中被保留，就从 `borders` 表读入其“已保留”状态和半径；
   - 对核心点做泊松选择，保留的点立即写入 PLY；距块边缘 ≤ halo 的保留点记入 `borders`，供后续相邻块使用；`borders` 只保留当前列和前一列，内存有界。
5. 处理完的块文件立即删除；结束后删除整个临时目录。

**为什么没有接缝**：泊松采样是一个顺序过程，跨块的一致性依赖“后处理的块能看到先处理的块在边界附近的选择”。`borders` 恰好提供了这一点，因此块边界处的效果相当于对整个点集按“块顺序 + 块内顺序”做了一次全局泊松采样。

**与预算的关系**：

- 块大小由预算决定，块大小又影响全局访问顺序。因此改变 `--simplify-memory-mb` 会使具体保留哪些点可能略有不同，但 4.4 中的覆盖距离和误差保证不变（当前合成测试中单块与多块结果均为 2549 点）。
- 预算是目标值而不是硬上限：块按平均密度划分，最密的块可能超出预算（真实数据最大块 425 万点）。
- 临时磁盘空间约每点 100 字节（`spool.bin` + 块文件 + halo 副本，两者不同时存在）。

## 5. 使用方法

```text
# 一条命令完成：缺失的深度图先估计，再流式融合 + 自适应简化
DensifyPointCloud -w depthmaps -i scene.mvs --resolution-level 2 --fusion-mode 0 --fusion-filter 2 \
    --geometric-iters 0 --postprocess-dmaps 0 ... \
    --stream-fusion 1 --stream-fusion-cache-mb 768 \
    --simplify-adaptive 1 --simplify-min-spacing 1.0 --simplify-max-spacing 2.0 \
    --simplify-error 0.5 --simplify-transition 30 --simplify-memory-mb 256
```

| 参数 | 默认 | 取值范围 | 含义 |
|---|---|---|---|
| `--stream-fusion` | 0 | 0/1 | 启用流式融合 |
| `--stream-fusion-cache-mb` | 2048 | ≥1 | 深度图/图像/掩码缓存预算（MiB） |
| `--simplify-adaptive` | 0 | 0/1 | 启用自适应简化（要求 `--stream-fusion 1`） |
| `--simplify-min-spacing` | 1.0 | [0.5, max] | 特征处采样间距（单位：局部 GSD） |
| `--simplify-max-spacing` | 2.0 | [min, 4] | 平坦处采样间距（单位：局部 GSD） |
| `--simplify-error` | 0.5 | (0, 2] | 被删点与保留点局部表面（质心）的最大落差（单位：局部 GSD） |
| `--simplify-transition` | 30 | [0, 1000] | 间距最多翻一倍所需的距离（单位：中位 GSD），越大过渡越平缓；0 关闭 |
| `--simplify-memory-mb` | 256 | ≥1 | 简化分块的工作内存目标（MiB），与融合缓存相互独立 |

调参建议：

- 平坦区想保留更多点：把 `max-spacing` 降到 1.5；想减更多：升到 3（点数约再减一半）。
- 细小起伏（如路沿、田埂）被抹平时：把 `error` 调小到 0.3。
- 仍能看到密度过渡时：把 `transition` 调大到 50～60（过渡更平缓，点数略增）；想让特征周围加密范围更窄：调小到 15～20。
- 噪声很大的数据：特征分数会偏高，导致减点偏少，这属于正常现象。

## 6. 实测结果

数据：180 张航拍深度图，`--resolution-level 2`，`--stream-fusion-cache-mb 768`，其余参数取默认。

| | 点数 | 峰值内存 | 耗时 |
|---|---:|---:|---:|
| 原始融合 | 19,082,657 | ~8.37 GB | 2m14s |
| 流式融合 | 19,082,657 | ~880 MB | 3m27s |
| 流式融合 + 自适应简化（第二版） | 8,369,312（−56.1%） | ~880 MB | 5m03s（其中简化 1m09s） |
| 流式融合 + 自适应简化（当前） | **6,525,424（−65.8%）** | ~880 MB | 7m54s（其中简化 2m52s） |

质量验证（以中位 GSD 为单位）：

- 输出是未简化结果的**严格子集**，没有重复点；
- 被删点到最近保留点的三维距离：p50 0.95，p99 1.86，p99.9 2.85；最大值 4.57 出现在厚噪声层（法向偏移在噪声带内）或局部 GSD 较大的区域，均在设计保证之内；
- 16% 的点被判为特征点（第二版为 35%，多出的部分主要是噪声和材质引起的误判）；
- 在三个 80×80 m 区域绘制保留点的三维间距图：第二版在同一田块内呈椒盐状，并在材质分界处有锐利跳变；当前版本的间距在数米范围内渐变，没有锐利分界。8×8 m 点分布图中，第二版田埂处的密度台阶变为低对比度的渐变；
- 简化共分 16 个块，块边界处未见接缝。

## 8. 已知局限

- 干净的 90° 屋脊只得到中等程度的加密：合成数据中屋脊保留 7.2%，两侧斜面 5.5%。原因是特征阈值要容忍真实数据的噪声。屋脊的几何精度主要由 `error = 0.5 GSD` 的质心误差限保证。
- 纹理只加密到约 1.5 GSD（纹理权重 0.5），以免材质和阴影变化在平面上产生密度边痕。
- 粗糙或倾斜的区域（植被、坡面）仍比平地密，这是真实的几何差异；俯视投影下倾斜面还会显得更密。
- 间距过渡带宽约 `T` 个 GSD（默认约 4 m），特征周围的加密范围因此更宽，点数比没有过渡限制时略多。
- `--simplify-memory-mb` 不是硬上限，点分布极不均匀时，单块可能明显超出预算。
- 改变简化内存预算可能使保留点集略有变化（保证不变）。
- 简化发生在融合之后，**融合阶段的耗时与 I/O 不变**；简化本身额外增加约 3 分钟（本数据，3g 特征邻域比 2g 计算量更大）。
- 流式模式不支持依赖内存点云的后处理（见 2.4）。
